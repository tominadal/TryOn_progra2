INTEGRIDAD Y CONCURRENCIA 06 / 13

Concurrencia y Transacciones: Garantías ACID

Prevención de sobreventas (Overselling) y Race Conditions mediante Bloqueo Pesimista.

El Problema: Race Condition en Checkout

Sobrevendiendo la última unidad (Stock = 1)

Cuando dos usuarios envían su orden simultáneamente, las lecturas concurrentes sin bloqueo ven stock disponible y ambas órdenes pasan, dejando el inventario en saldo negativo.

Línea temporal sin bloqueo pesimista: FALLO ACID
T0: Stock = 1 en tabla GarmentStock
T1: Usuario A ejecuta SELECT stock (ve 1)
T2: Usuario B ejecuta SELECT stock (ve 1)
T3: Usuario A confirma y decrementa (Stock = 0)
T4: Usuario B confirma y decrementa (Stock = -1 ⚠)
Solución TryOn Hub: with_for_update() serializa las transacciones a nivel de fila.
# Bloqueo Pesimista en Checkout Atómico (cart_service.py)
with db.begin():
  # SELECT ... FOR UPDATE bloquea la fila hasta el commit
  stock = db.query(GarmentStock)
    .filter_by(garment_id=item.id, size=item.size)
    .with_for_update()
    .first()

  if not stock or stock.quantity < item.qty:
    # Rollback automático al lanzar excepción
    raise InsufficientStockException(
      "Stock no disponible para esta variante"
    )

  stock.quantity -= item.qty
  order = Order(user_id=user_id, status="PAID")
  db.add(order)
  # Atomic commit: stock descontado e idempotencia asegurada

# Implementación del Patrón Observer (Batch Processing)
class BatchImportSubject:
  def __init__(self):
    self._observers: List[Observer] = []

  def notify(self, event: BatchEvent):
    for obs in self._observers:
      obs.update(event)
